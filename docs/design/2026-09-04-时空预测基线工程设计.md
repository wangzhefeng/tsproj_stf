# 时空预测基线工程设计

## 1. 目的

本设计定义 `tsproj_stf` 从文献资料仓库演进为可复现时空预测实验工程的首个正式架构。

项目采用“**项目自有数据与评估契约 + 固定版本 BasicTS 训练后端**”路线：由本项目掌控影响实验结论的科学协议，由 BasicTS 提供通用训练循环、模型、checkpoint 与设备执行能力。

首批实施范围为 M0～M2：建立工程基础，验证依赖兼容性，实现可信的数据与评估协议，并在 METR-LA 上完成 Persistence 与 STID 的端到端基线。

## 2. 已确认决策

1. 项目路线采用路线 B，不把 BasicTS 当作不可检查的黑盒，也不从零重复实现完整训练框架。
2. 首个端到端数据集使用公开基准 METR-LA，不同时引入私有电力数据清洗问题。
3. 首个训练模型使用 STID；Persistence 作为无训练基线先行。
4. 首批实施不包含 Graph WaveNet、电力数据接入、分位数预测和大规模模型横向比较。
5. 项目内部数据契约独立于 BasicTS；BasicTS 通过适配层消费模型所需视图。
6. 正式实验必须记录数据、配置、代码、环境和随机种子信息，不接受仅保留终端日志。
7. 开发环境统一使用项目根目录 `.venv` 和 `uv`；项目依赖统一通过 `uv add` 管理。
8. BasicTS 使用发布版 `BasicTS==1.1.0` 并由 `uv.lock` 固定完整依赖和制品哈希；不得依赖可变的 `master`。本次源码审查参考提交为 `c2bb6e31e591167e84459775a21a62e70a5893ce`。

## 3. 目标与非目标

### 3.1 首批目标

- 建立可安装、可测试、可从命令行运行的 Python 工程。
- 定义时空数据、节点、时间戳、缺失掩码和图结构的统一契约。
- 保证时间切分、滑窗、归一化和指标计算没有数据泄漏。
- 在 METR-LA 上运行 Persistence 与 STID。
- 输出 overall、horizon 3、6、12 的 MAE、RMSE、MAPE。
- 保存可复现实验产物，并能从已保存配置重新运行。

### 3.2 首批非目标

- 不实现自有通用训练框架。
- 不复刻所有 STGNN 论文模型。
- 不实现图结构学习；STID 本身不使用邻接矩阵。
- 不接入私有电力数据。
- 不实现 MPS 专用执行路径。
- 不把单次训练结果包装成模型优劣结论。
- 不以跨论文表格数字作为直接验收阈值。

## 5. 数据契约

### 5.1 项目内部结构

项目内部统一采用以下逻辑结构：

```text
values       float32 [time, node, feature]
observed     bool    [time, node, feature]
timestamps   datetime64/int64 [time]
node_ids     str/int [node]
graphs       dict[str, float32 [node, node]]
feature_names list[str]
target_features list[str]
```

约束：

1. `timestamps` 严格递增且采样间隔固定。
2. `node_ids` 唯一，顺序一旦进入 processed dataset 即不可隐式改变。
3. 所有图的两个节点轴必须与 `node_ids` 完全一致。
4. `observed` 是缺失事实的唯一来源；真实零值不得被默认视为缺失。
5. 数据进入训练前必须转换为 `float32`，节点 ID 和时间信息除外。
6. 数据契约保留 feature 轴，即使首个 METR-LA 实验只有一个目标特征。

### 5.2 BasicTS 适配视图

BasicTS 1.0 的预测样本约定为：

```text
inputs             [batch, input_len, num_features]
targets            [batch, output_len, num_features]
inputs_timestamps  [batch, input_len, num_timestamps]
targets_timestamps [batch, output_len, num_timestamps]
```

其内置 STID 把 `num_features` 用作被联合预测的序列/节点维度，并输出 `[batch, output_len, num_features]`。[5][7][8]

因此首个 METR-LA 适配器执行：

```text
project values [time, node, 1]
        ↓ select target feature
BasicTS view   [time, node]
```

适配器必须显式校验节点数、输入长度、输出长度和时间特征数量，不做静默 reshape。

## 6. 数据切分、窗口与归一化

### 6.1 METR-LA 协议

METR-LA 包含 207 个传感器、34,272 个 5 分钟时间点及传感器图。[6]

首个实验固定：

```text
input_len  = 12
output_len = 12
split      = 0.7 / 0.1 / 0.2
strategy   = chronological
```

采用 BasicTS 当前 METR-LA 标准的 `7:1:2`，不把一般性示例中的 `6:2:2` 强加到该 benchmark。

### 6.2 切分语义

1. 先根据时间轴计算 train、validation、test 边界。
2. 每个 split 内独立生成滑窗。
3. 窗口不得跨越 split 边界。
4. validation 和 test 不参与任何参数、阈值或归一化统计量拟合。
5. train 窗口生成后允许 DataLoader shuffle；时间切分本身不得随机化。
6. validation/test DataLoader 不 shuffle。BasicTS 当前配置也区分 train shuffle 与 val/test 非 shuffle。[9]

### 6.3 归一化

- 使用 Z-score。
- 统计量仅从 train split 的有效观测计算。
- 首个单目标节点预测按节点分别计算均值与标准差。
- 标准差为零时使用 `1.0`，同时在数据清单记录常数节点。
- loss 在标准化空间计算。
- 正式测试指标在 inverse transform 后的原始量纲计算。
- BasicTS 配置必须显式设置 `rescale = true`，确保模型输出在计算正式指标前恢复原始量纲。
- 项目自有 scaler 与 BasicTS scaler 必须用契约测试比较统计量和往返结果。

BasicTS 当前 scaler 支持从训练数据拟合并在 task flow 中进行 transform/inverse transform；本项目仍保留独立校验，以避免后端变化悄然改变实验语义。[9]

## 7. 缺失值规则

- METR-LA benchmark 的缺失语义遵循所选固定数据版本的 manifest。
- 不使用“数值等于零即缺失”作为项目全局规则。
- 数据准备阶段生成 `observed` mask。
- 输入缺失值填充值只用于模型计算，不改变 mask。
- loss 和指标仅在有效目标位置计算。
- 若某个 horizon 没有有效目标，实验必须失败并报告，而不是输出零或 NaN 后继续。

## 8. 模型与实验顺序

### 8.1 Persistence

定义：未来每个 horizon 均预测为输入窗口最后一个有效观测。

用途：

- 验证标签对齐和 horizon 顺序；
- 建立无训练下限；
- 发现异常低误差导致的数据泄漏；
- 验证指标与产物链路不依赖 BasicTS。

### 8.2 STID

STID 使用历史序列 embedding、节点身份 embedding，并可选时刻/星期 embedding；它不消费邻接矩阵。[7][8]

首个 STID 实验启用：

- spatial/node identity embedding；
- time-of-day embedding；
- day-of-week embedding；
- one-shot 12-step output；
- MAE loss；
- validation MAE early stopping。

首个训练链路只验证 STID，不把 STID 结果解释为“图结构有效”。

### 8.3 后续模型门禁

只有 M0～M2 验收全部通过后，才进入 Graph WaveNet：

1. predefined graph only；
2. adaptive graph only；
3. predefined + adaptive graph。

Graph WaveNet、AGCRN、MTGNN、电力多图与分位数输出均不属于首批实现。

## 9. 评估协议

正式指标：

- MAE；
- RMSE；
- MAPE；
- WAPE 作为零值敏感场景的辅助指标。

报告维度：

- overall；
- horizon 3；
- horizon 6；
- horizon 12；
- 3 个固定 seed 的均值与标准差。

规则：

1. 所有正式指标使用反归一化后的预测和真实值。
2. 所有指标共享同一个有效目标 mask。
3. horizon 配置使用面向用户的 1-based 编号，内部索引转换必须有单元测试。
4. MAPE 必须记录分母保护与 mask 规则，不作为唯一模型排序指标。
5. BasicTS 当前支持 target metric、MAE loss、常用指标和按指定 horizon 评估，但项目实现独立 NumPy/Torch 校验函数对结果抽样复核。[9]
6. 不直接拿不同论文的表格数字判定成功；需要在固定代码、数据和配置下比较。

```text

```

多 seed 汇总是独立 artifact，不覆盖单次 run。

## 11. 错误处理

以下情况必须立即失败：

- 时间戳非单调或频率不一致；
- node ID 重复；
- 图节点顺序或 shape 不匹配；
- split 为空或不足以构造一个窗口；
- scaler 收到 validation/test 数据参与拟合；
- 模型输出与目标 shape 不同；
- 预测包含非有限值；
- horizon 越界；
- 正式 run 的配置、manifest 或 metrics 未成功落盘；
- 已存在 run ID 对应不同 resolved config。

错误信息必须包含 dataset、split、shape 和相关配置值，不能只抛出无上下文的底层异常。

## 15. 风险与处理

### 15.1 BasicTS 依赖兼容性

BasicTS 1.1.0 的发布元数据要求 Python `>=3.9`，但没有声明 PyTorch；其仓库 `requirements.txt` 固定 NumPy 1.24.4，而发布元数据对 NumPy 不固定。[2][3][4]

处理：显式添加 PyTorch，以 `uv.lock` 为唯一解析结果，并在 M0 先验证后开发。

### 15.2 macOS MPS

本次审查的 BasicTS 源码没有 MPS 执行路径，设备配置主要面向 CPU/CUDA。

处理：Mac 本地只承诺 CPU smoke；正式全量训练优先使用 CUDA。首批不为 MPS 修改 BasicTS 内部设备层。

### 15.3 MAPE 零值问题

处理：明确 mask 与分母保护，同时报告 WAPE，不用 MAPE 单独裁决模型。

### 15.4 STID 与图结构无关

处理：把 STID 标记为节点身份基线；只有 M4 图消融可以支持图结构增益结论。

### 15.5 上游 API 漂移

处理：固定 BasicTS 1.1.0 和 `uv.lock`；适配逻辑集中在单一包；通过合同测试检测变化。

### 15.6 数据下载不可自动化

BasicTS 当前要求将预处理数据放在本地目录，远程自动下载仍未实现。[2][10]

处理：本项目提供显式 prepare 命令、来源说明与 fingerprint；网络失败时保留已下载原始文件，不产生伪造数据。

### 16.1 真实基准结果

train-mean cold-start Persistence 的 overall MAE 为 `4.2348`。STID 三 seed 的 overall
MAE 为 `3.1490 ± 0.0074`（样本标准差）。Graph WaveNet
CPU 参考配置的单 seed overall MAE 分别为 fixed `3.7620`、adaptive `3.7354`、

| METR-LA 存在节点连续缺失超过完整 12 步输入窗。 | Persistence 默认仍在无历史时失败；正式 benchmark 显式使用节点 train-only 有效均值 cold-start，不把零当缺失或预测事实。 |
| 初次 STID seed 42 和 Persistence run 被中断，留下受保护 partial 目录。 | 不删除、不覆盖取证目录；STID 完整结果使用 `_formal` 前缀，Persistence 加固结果使用 `_train_mean` 前缀。 |
| Graph WaveNet 在 macOS CPU 上单 epoch 成本显著高于 STID。 | 三模式统一使用 15 epochs、4 channels、完整 12 步感受野的参考配置；只比较相同容量的图模式，不包装成论文级性能结论。 |
| BasicTS 默认每个 epoch 都运行 test。 | Graph WaveNet 将 `test_interval` 设为训练上限之后，只按 validation MAE 早停，训练结束再以最佳 checkpoint 运行一次 test。 |
| 当前没有私有电力数据。 | M5 仅以非敏感合成 fixture 验证迁移契约；真实数据、真实多图质量和报价价值仍是外部门禁。 |
